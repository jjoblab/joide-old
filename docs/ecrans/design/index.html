Mouvement

180 ms standard, 240 ms entre écrans ; entrées latérales directionnelles sur téléphone (axe X partagé), fondu discret sur grand écran — la distinction ScreenTransition de CodeAssist (ADR-É1, leçon 6). Élévation en sombre : liseré supérieur clair + ombre douce, jamais d'ombre dure.

Franchise — le motif d'UI de JoIDE

Les écarts s'affichent avant le lancement. Modules Android non construits sur appareil, dépendances non résolues : la console les dit AVANT, jamais après (« jamais d'omission muette », lot F).
L'aperçu ne ment jamais. XML en frappe = dernier rendu valide conservé ; ressource manquante = repli natif annoncé ; classe inconnue = MockView (contrat lot E porté à l'écran, ADR-É7).
Les sorties de build s'affichent estompées. Pendant qu'elles se construisent, le nœud build-joide est visible, grisé, avec sa raison — jamais présenté comme source, jamais caché.
La mort du service est un événement, pas un état zombie. « Build interrompu : l'IDE survit ; le prochain build le relance » — l'UI ne meurt jamais avec le :build (ADR-043, lot F).
